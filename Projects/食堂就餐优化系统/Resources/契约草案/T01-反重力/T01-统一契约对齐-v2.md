## 3. 存储层、生命周期与交互规则映射

### 3.1 实际记餐（MealLog）与存储设计
- **记录结构**：
  - `recordId`: 稳定记录 ID（前端 UUID 生成）；
  - `confirmationId`: 操作幂等键（前端每次触发确认时生成并在防抖期内锁定）；
  - `businessDate`: 设备本地自然日（`YYYY-MM-DD`）；
  - `tzOffsetMinutes`: 时区偏移（如北京时间 480）；
  - `meal`: `breakfast` | `lunch` | `dinner` | `other`；
  - `status`: `active` | `superseded` | `revoked`（核心仅统计 `active` 记录）；
  - `revision`: 版本计数器，从 1 递增；
  - `replacesRecordId` / `supersededByRecordId`: 改撤双向指针；
  - `confirmedAt` / `revokedAt`: ISO 8601 时标；
  - `items[]`: 记餐快照（含 `itemKey`, `offerId`, `dishId`, `nameSnapshot`, `portionCode`, `quantity`, `unitPriceCents`, `priceKnown`, `nutrition`, `nutritionBasis`）。
- **确认实吃幂等性**：
  - 小程序存储层在写入前校验 `confirmationId` 与 `recordId`；
  - 若已存在同 `confirmationId` 的成功记录，直接返回已存记录，严禁重复入账累加营养与支出。
- **改撤与历史保留**：
  - 用户修改历史实吃时，原记录 `status` 变为 `superseded`，指向新记录；新记录版本 `revision + 1`，`replacesRecordId` 指向原记录；
  - 用户撤销实吃时，原记录 `status` 变为 `revoked`，记录 `revokedAt`；
  - 核心计算仅读取当日有效 `status === 'active'` 的日志快照。
- **餐次结束（Ended Meals）**：
  - 用户主动放弃某餐次规划（如“不吃了”）时，前端将该餐次加入 `state.endedMeals[]`；
  - **绝不伪造 `SKIPPED` 摄入记录或生成 0 元虚假消费日志**；
  - 核心在 `planningMeals` 中直接排除 `endedMeals`。

### 3.2 业务日期与状态作用域
- **业务日期**：严格以小程序客户端本地时间为准；
- **跨日切换**：
  - 冷启动或切回前台时，检测本地日期变化；
  - 发生跨日时，清空昨日临时锁定（`itemLocks`, `windowLocks`）、清空当日售罄（`soldOut`）及已结束餐次（`endedMeals`）；
  - 重新基于新日期初始化每日规划状态；
- **售罄状态作用域**：严格绑定 `业务日期 + 窗口ID + 餐次 + 菜品ID`，仅当日有效，支持手动提前解禁。

## 4. WASM 接口与调用生命周期映射

C ABI 导出函数完全满足小程序端的调用与内存管理规范：

```cpp
extern "C" {
  unsigned int mp_api_version(void);
  const char*  mp_contract_version(void);   // 静态常量，JS 绝不调用 free
  char*        mp_alloc(unsigned int bytes);
  void         mp_free(char* p);
  char*        mp_plan(const char* requestJsonUtf8);
  char*        mp_nutrition_target(const char* targetRequestJsonUtf8);
  char*        mp_validate_menu(const char* catalogJsonUtf8);
}
```

### 4.1 调用与缓冲区释放生命周期
1. **调用前内存准备**：
   - JS 将入参对象序列化为 UTF-8 字节数组（`TextEncoder`）；
   - 调用 `mp_alloc(bytes.length + 1)` 在 WASM 堆上分配输入缓冲区并写入，末尾补 `\0`；
2. **执行与结果拷贝**：
   - 调用 `mp_plan(inPtr)` 获取 `outPtr`；
   - 若 `outPtr === 0`，代表 WASM 端内存耗尽，前端直接包装为 `INTERNAL_ERROR` 资源耗尽错误；
   - 否则，JS 立即从 WASM 堆中将结果 UTF-8 字符串完整拷贝到 JS 堆（`TextDecoder`）；
3. **`finally` 安全释放机制**：
   - 无论执行成功或抛出异常，在 `finally` 块中严格执行：
     - `mp_free(inPtr)` 释放输入缓冲区；
     - `mp_free(outPtr)` 释放输出缓冲区；
   - 两端指针绝不复用，绝不泄漏；
   - `mp_contract_version` 为静态指针，只读不释放；
4. **单实例串行与隔离**：
   - 小程序运行时维护单个 WASM 实例；
   - 规划任务通过 Promise 串行队列调度，避免并发重入导致内存冲突。

## 5. 实现阻塞差异核查结论

依据任务提示词要求，针对页面、调用及本地存储实现条件进行全方位核查：

1. **入参获取能力**：
   - 设备日期、时区偏移、用户信息、菜单数据、日志记录在微信小程序端均可通过标准 API（`Date`, `wx.getStorageSync`）完整获取，无任何前端缺失字段。
2. **数据表示与类型兼容**：
   - 候选契约全面使用整数分（金额）、整数 kcal（能量）、整数 0.1g（宏量）、毫米（身高）、克（体重），全部在 JavaScript 安全整数范围（$2^{53} - 1$）内，杜绝了浮点误差风险。
3. **计算职责边界**：
   - 页面端不承担任何营养目标公式计算、排序规则打分或套餐规则展开，所有业务核心重算均交由 C++ 核心执行，前端职责纯粹，易于维护与测试。
4. **异常与回退表现**：
   - 错误信封分层清晰，业务状态（`OkPartial`, `NoFeasibleWithinBudget` 等）均能直观映射到 UI 提示文案，不依赖吞错或伪造假数据。
5. **米饭半份与套餐价格一致性**：
   - 半份米饭严格与整份同价映射，前端表单和展示逻辑无歧义；套餐按总价结算且含饭不重收，逻辑闭环。

**核查结论**：
> **页面/调用/存储可按候选接入，未发现实现阻塞差异。**
