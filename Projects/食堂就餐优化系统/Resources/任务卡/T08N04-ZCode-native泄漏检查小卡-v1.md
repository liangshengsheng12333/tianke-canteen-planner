# T08N04｜native泄漏检查

GLM5.3子代理；先读T08N总卡、M03内存工具缺项和当前platform_native.cpp。可提前在本路准备检测驱动，最终必须读取主窗口N01/N02/N03汇合后的同一隔离候选，记录完整源码/产物身份；不碰生产，不与正式性能运行竞争CPU。

优先现有MSVC/UCRT调试堆：本路测试驱动与全部参与检测的自写核心源码统一调试运行库编译（如/MDd），通过 `_CrtMemCheckpoint/_CrtMemDifference` 等检查预热前后批次，并能定位泄漏。native实际RawAlloc使用malloc/free，核驱动确实覆盖该分配路径。不要往生产加入检测框架/计数器，不安装工具、不改ACL；不可用则记录实际错误，不拿ASan detect_leaks不支持或WASM页平稳冒充完成。

必须有已知少量泄漏阳性对照：测试驱动临时分配不释放可被检出，释放后差异消失，证明检测通路有效。区分运行库一次性初始化和核心残留，不能随意忽略报告。所有生产入口遵守输入mp_alloc、输出读取后mp_free、context释放等实际所有权。

在同一测试进程预热后重复请求，覆盖四个主要入口（plan/target/menu/offer）、三算法、非法输入、null与真实正时限；按代价分批设次数并保存逐批计数和原始检测输出，昂贵子进程≤25秒。测试缓存/请求字符串在checkpoint之外初始化，作用域内真正释放，说明覆盖不包含什么；若有残留给最小请求与栈/分配证据，只报不修。

输出 `Resources/报告/T08N04-ZCode-native泄漏检查-交付反馈-v1.md`，证据同名 `…-证据-v1/`，包含构建命令/运行库一致性、阳性对照、被测最终源码与exe哈希、批次原始结果/限额/未测。结论限定为“该请求集未检出泄漏”，不宣称任意输入绝无泄漏。
