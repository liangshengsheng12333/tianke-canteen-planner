# 第一版菜单、教程与用户/开发构建｜简要PRD v2

2026-10-25。用户已明确“按此方案执行”批准菜单更新与四步教程，并明确“按两种构建收口”批准本v2用户/开发构建区分。**三项范围均已确认**，按下述依赖派发实现；确认不等于已执行或验收完成。

## 当前问题与已核事实

当前为同一代码/预览包：app.json注册pages/dev/index，“我的→数据管理→诊断信息”可达；今日页有技术信息折叠，菜单页有原始JSON和哈希字段。简易/完整仅区分营养展示量，不是开发权限或构建模式。用户手机保存旧官方菜单曾导致多数菜热量未知，更新后恢复；新用户也缺使用教程。

## 两项已确认范围

1. 包内最新版官方菜单作为默认；只对精确识别的旧官方菜单处理升级，复用现有存储/菜单替换规则，保留历史快照、已吃记录及用户自定义导入菜单。旧计划失效后需重新生成，失效锁定不静默删除。不开新联网菜单服务，不重估当前62报价。
2. 四步短教程：档案与目标→推荐/自选→确认/改撤补记→月历与设置。首次可跳过，“我的→使用教程”重看，不反复弹、不阻塞使用，沿用现有主题和轻量风格，不介绍未实现的增肌功能。

## 建议新增：同一代码与核心，两种构建

| 内容 | 用户构建 | 开发构建 |
|---|---|---|
| 选餐、记餐、历史、预算、三算法、营养计算 | 保留 | 与用户构建一致 |
| 简易/完整、浅深色/跟随系统 | 均保留 | 均保留 |
| 更新官方菜单、文件备份/恢复、教程 | 保留，普通文案 | 保留 |
| 模拟夹具、故障注入、性能测试、ABI探针、原始JSON/哈希诊断面板 | 不注册开发页面、无可达入口；不要求用户接触开发信息 | 保留 |
| 手工编辑/导入开发菜单JSON | 不出现在日常用户流程 | 保留供维护调试 |

复用业务代码、菜单与C++/WASM，不另写一套“简化算法”；用户版不是仅剩简易模式，也不能拿开发版成绩冒充用户包实际表现。构建配置生成用户/开发产物与各自manifest；编译前检查依赖关系，不能盲删仍被业务代码引用的模拟模块。优先去掉整个开发页面和可达入口，按引用图裁掉纯开发数据；保留正常错误提示和必要内部异常处理。

不提供给普通用户的“开发者模式开关”，不靠连点/密码充当版本隔离。备份导入仍要保留用户可操作路径，不因去除原始JSON面板丢失恢复能力。无需新增账号、权限系统或服务器。

## 成功标准

- 用户构建新装与旧官方菜单升级后均显示当前估算热量，重开保持；自定义菜单/历史记录不被覆盖。
- 首次教程可看/跳过、重开不再强弹、我的页可重看，简易/完整及主题显示正确。
- 用户构建不能从导航或直接页面路由打开开发诊断页，正常业务/文件备份恢复仍可用；开发构建可运行原诊断。
- 两个构建的同菜单同请求计算输出一致，核心WASM哈希一致；对用户包做实际页面与手机验证，不能仅测开发入口。
