# 答辩事实补充

## 可直接采用的项目介绍

天科食客面向真实食堂选餐：把窗口菜单、个人目标、预算和当天已确认的就餐记录连接起来。user-v5 提供三种单次择一的推荐方式，也允许用户手动自选并查看记录。C++17 共享核心编译为本地 WASM 供小程序调用，并保留 Native CLI 供电脑侧验证。

## DP 优化的准确口径

同一 G2 两餐 DP 请求的 PC/Node 五次中位数：旧冻结 WASM 为 23,455.864 ms；T04A19 新核心交付方结果为 70.999 ms，P01 独立复测为 86.300 ms；T06i user-v5 接入包为 69.534 ms。优化显著降低了这组请求的 PC 运行时间，但原 ≤50 ms 目标未达到，用户接受本轮结果。所有数值都是 PC/Node 计时，不代表手机速度。

## 可复用的简短答辩

> 项目把真实食堂菜单、个人目标、预算和实际就餐记录连到同一条本地流程。小程序允许用户选择贪心、动态规划或分支限界，也能手动自选。针对两餐 DP 的重复扫描做优化后，PC 上同一请求的中位运行时间从约 23.46 秒降到约 71 毫秒；P01 独立复测为 86.3 毫秒。原 50 毫秒目标仍未达到，这些数据也不能代替手机性能测量。

## 常见问题

- **三个算法会同时运行后投票吗？** 不会。用户每次选择一种方法。
- **贪心一定找到局部最优吗？** 不保证。它是启发式方法，且不保证全天最优。
- **DP 的状态数等于总工作量吗？** 不等于。单/双餐保留上限为 20,000，三餐为 32；候选生成、去重与截断仍影响处理量和最优性边界。
- **BnB 节点上限能保证运行时间吗？** 不能。最坏工作量仍取决于搜索树；节点数限制不等于墙钟时间限制。
- **营养数据都是实测吗？** 不是。部分是有来源和假设的估算；未知不按零处理。
- **产品已经全验收或上线了吗？** 没有。P09审查支持 user-v5 用于体验/课程演示；整项 PRD 未全通过，也未生产发布。
