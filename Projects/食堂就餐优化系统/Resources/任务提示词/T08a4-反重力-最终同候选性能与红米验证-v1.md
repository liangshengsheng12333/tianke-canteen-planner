## 性能口径和判定

### PC/native 与 Node/WASM

针对 G0—G3 三算法保存同输入完整输出及状态、调用次数、实际限额、进程超时和资源采样。native、Node WASM 和 Redmi 数据分开报告；Node 与模拟器只用于辅助定位，不作为真机门槛证据。native 资源/内存检查单列方法和覆盖限制，WASM 页数稳定不证明 native 无泄漏。

### Redmi K90 Pro Max

记录设备型号（Redmi K90 Pro Max）、系统版本、微信版本、基础库版本、构建/预览身份、实际包内 WASM 运行时身份、必需 import 绑定、时钟来源/单位/单调性及前后台有效性。确认真实加载 111521 B 候选，不能只看源码常量或旧缓存。分别验证默认 `wallClockMs=null` 路径和一个独立的短正 deadline 诊断路径：null 路径不得读取时钟；正值路径需证明真实 `mp_monotonic_ms` 被绑定并可触限/得到明确错误。正 deadline 结果只证明时钟接缝行为，不得代替正式默认配置测量。

1. **WASM 核心 `mp_plan`**：从本次调用前至返回后，包含解析、搜索和输出，排除模块首次加载与页面绘制；G1—G3 每组正式中位数目标 `≤50 ms`。
2. **页面出方案**：真实点击生成开始，到该次完整结果首次实际可见渲染结束；每组正式中位数目标 `≤300 ms`。当前 `pages/dev/index.ts` 的页面计时止于 `setData` 回调（渲染层接收），这不是实际可见渲染证明；不能把它记成通过。若现有手机/自动化通道无法观察真实可见完成，保留回调值并标“替代口径/未测门槛”，列明所缺观测。
3. **WASM 峰值**：G1—G3 重复调用期间记录 `memory.buffer.byteLength/65536` 的完整采样序列、每组最高页数及分配失败；目标 `≤768 pages`（48 MiB）。不得用 RSS 或手机总内存替代 WASM 线性内存。
4. **桥接与其它体验项**：另列 UTF-8 编码、输入/结果复制、显式释放、桥接往返；首次获取模块、冷启动至可交互、首次出方案均独立记录，不混入核心-only 指标。
5. **真实操作**：完整操作一天；离线可用；关闭/重开；前后台切换恢复；跨日后状态与过期结果处理。记录每步前后可观察数据/日志及当前候选身份，过期结果不能覆盖新输入。跨日优先使用应用已有的日期选择/自然日期变化；不得改手机系统时间、注入假时钟或清空已有用户数据。若本轮未自然跨日且应用无隔离日期入口，明确列未测。只登记实际发生的设备操作；A11 若无真实朋友反馈就写“待完成”，不能把 AI/执行者自测冒充朋友试用。

性能阈值沿 v2 原值，不事后放宽。任一目标超限即对应组不通过，整体 A10 不可先判通过；未获得真实渲染、运行时或设备数据就明确未测/阻塞。截断结果如实呈现 approximate、searchComplete 和 cap；没有可行方案时不能冒称已证明无解。正 `wallClockMs` 仅作独立时限诊断，不替代默认 `null` 矩阵。
