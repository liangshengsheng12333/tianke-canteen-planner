## T01 已冻结的测量口径

依据 `Resources/契约/T01-v1.2-candidate/contract-v1-candidate.md` §12、`Resources/任务卡/T01-契约与营养配置.md`、`Resources/任务卡/T07-实验与一致性.md`、主 PRD v0.2 §6.1，以及 `Resources/报告/T01-P01-冻结裁定-20261020.md`。T01 冻结测量流程，不含实测数字或性能目标。具体执行以下已定口径：

- 规模维度：`M` 规划餐数、`W` 每餐窗口数、`D` 每窗口合法 offer 数、`K` 每餐最多菜品数、`C` 单餐候选数、`S` DP 状态数、`N` BranchAndBound 搜索节点数。每条数据保留原始维度值及对应输入/菜单身份。
- 分组：使用 G0–G3。G0 为极小链路规模，G3 为 T03/T02 已界定的真实菜单规模。各组精确成员、G1/G2 阶梯和本次安全运行上限**尚未冻结**，由 P01 在本卡开工放行记录中填明；不得自行发明具体规模或把 T07a 的 10/15/15 合成候选数当性能上限。
- 计时：分别记录四类互斥数据——核心-only（仅实验构建计数器分段 parse/validate、candidate、solve、serialize，不混入正式结果）、JS 调用往返（不含拷贝/释放）、拷贝/释放、页面端到端。T07b 当前只具备原生 CLI 与 WASM/宿主测量条件时，逐项标清哪些计时类别实际执行、哪些“未运行/不适用”，不得伪称测得页面端到端。
- 重复与统计：每个测量项至少 5 次；保留全部原始值，并报 median/min/max。环境、工具版本、菜单规模、输入身份和运行限额随结果记录。不得用单次样本验收。
- 资源：记录平台峰值内存、WASM 内存页、`.wasm` 大小、DP 状态数及 BranchAndBound 节点数；分平台/运行时报告，不混算。
- 一致性/正确性复用既有口径：确定性限额、`wallClockMs=null`；这不等于性能计时规则，也不能用性能超时替代正确性裁定。
- 注释率：自写 C++/TS（`core/`、`miniprogram/src/`），排除第三方、生成物、构建产物、样例；使用 `cloc` 或仓库脚本，分母为非空代码行、分子为有效注释行，报告原始计数与排除清单，课设要求至少 20%。

T01 未冻结各规模组的具体输入数量、响应目标、峰值内存/节点硬上限或其他资源阈值。正式运行前须由 P01 在本卡填写：G0–G3 的具体成员及输入集、每组运行上限/停止条件、适用环境、响应目标（如尚无目标，明确写“本轮仅画像，不据此判 A10”）、平台资源限额和超限记录方式。任何数字没有一手裁定或明确输入来源时保留“待 P01 定界”，不推断、不沿用旧反馈作目标。

T02 只提供背景证据，参照 `Resources/报告/T02-P01-功能门禁与后续派工裁定-20261020.md` 与 `Resources/报告/T02-反重力-微信与真机验证-交付反馈-v2.md`。P01 将红米端 8 ms 明确裁为单次用户回报，不能替代至少 5 次热测、冷启动及分项数据，也不是性能验收阈值。后者中的本机冷加载/首次执行/五次热运行数据属于 Windows/Node.js 宿主，须与红米真机分开标注；不得把它们冒充本次固定候选的真实菜单全规模结果。

## 验证范围

仅对上文 P01 固定的同一候选及批准规模执行：

1. **三算法规模实验**：覆盖 `greedy`、`dp`、`branchAndBound` 与 P01 批准的各组。每次记录算法、`M/W/D/K/C/S/N`、输入/菜单和二进制身份、重复序号、原始耗时、方案质量/合法性、状态或节点数、搜索完整性、截断原因、近似标记、实际限额及是否触顶。分开记录原生 CLI 与 WASM 可运行宿主，不混合硬件/运行时数据。
2. **算法复杂度与支持范围**：依据本次固定候选源码，说明各算法在窗口、offer、单餐候选、DP 状态和 BnB 节点维度上的增长因素、剪枝与截断影响，并用测量数据核对趋势。不得仅凭有限样本宣称渐近复杂度或保证上限。资源限额触发时，已有方案标出近似/限制原因；无方案时注明“限额内未找到”，不能说已证明无解。Greedy 的非最优性质如实说明，不要求算法互相胜出。
3. **工程验证**：只在隔离副本按仓库现有流程构建和检查。记录源码清单、工具链版本、完整命令、退出码、自有代码 warnings/errors、二进制哈希；按 T01 注释率口径提供计数；使用当前环境已有的内存检查工具并明确覆盖范围、命令和原始报告。已知旧工具链勘察显示 AddressSanitizer 可检测越界但该 Windows 平台不支持泄漏检测；须在本次环境实际复核，不能据旧报告宣称本候选无泄漏，也不得为此安装新工具或修改生产代码。
4. **版本化性能配置草案**：按本次实测建立配置草案，区分测得事实、候选阈值和 P01 已冻结目标；列出输入规模范围、适用平台/算法、计时边界、重复/统计、资源/响应限制、超限语义和证据来源。T01 未给出的数字只能基于本轮完整数据作为明确标注的建议值，交 P01 决定；没有实测支撑的字段留“待测”。本轮不得自行宣布 A10 通过，P01 应在 T08 前正式冻结性能配置。
