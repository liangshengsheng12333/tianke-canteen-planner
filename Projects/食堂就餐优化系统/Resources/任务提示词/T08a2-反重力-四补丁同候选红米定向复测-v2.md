## 测试状态与四组操作

使用开发预览中的明确测试数据。正常 UI 建档、改测试预算、换菜、锁定、确认、撤销、导出备份、预检并替换菜单均是本卡获准操作；正式资源文件不编辑。通过 UI 切换已有示例/测试菜单与西一菜单时，逐场景记录 runtime menuVersion，代码候选始终相同。切换前保留测试状态快照/常规备份，不清除或覆盖用户真实就餐记录。若只有某个例子缺安全数据，单列该例未测并继续其余例子。

1. **连续换菜及保护**：在现有菜单中分别测试单菜餐次、多菜餐次，连续换至少两次；换菜选择约束不显示成用户锁，最新选择保留。用户显式锁定的菜仍受保护；已确认餐次换菜应被拒绝且实际记录不变。多菜可用已有示例菜单，不把它称为正式食堂数据或性能覆盖。
2. **菜单切换后解除**：先有换菜选择约束，再显式锁定一道菜，通过正常预检/确认入口替换菜单。内部选择约束随旧计划作废，用户锁仍保留；提示数量与实际一致。首页解除失效用户锁后能继续规划，无 `undefined` 或解除死局。已有样例不足时记录具体缺口，不用控制台改真实存储来伪造触控结果。
3. **预算**：设置明确测试预算，分别确认部分餐次与全部餐次，核实实际支出只算一次、已处理餐次不再算待吃计划；再降低测试预算以覆盖真实超支。保留预算、实付、剩余、待吃计划价和超支额的前后值；已吃快照不能被新推荐覆盖。
4. **未知与数字零**：用西一营养未知菜检查详情显示“营养未知/待补全”，不误显 0 或“待补全g”。数字零显示对照可使用既有 f04 明确标注的模拟 fixture（如可通过正常 UI 导入为测试菜单），只能证明格式语义，不能声称真实菜品营养为零；若无可用真机零值样本，单列该项未测并引用 f04/P01 已有离线零值证据，继续其余实机验证，不编造数据来源。
