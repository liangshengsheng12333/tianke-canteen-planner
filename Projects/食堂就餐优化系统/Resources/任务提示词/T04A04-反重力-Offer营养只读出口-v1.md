## P01确定的接口

只实现以下已定接口，不另行设计第二种入口或扩展业务：

- 新增 C ABI：mp_offer_nutrition(const char* input, uint32_t length)。
- 输入协议复用现有 BuildResultBlock、RunContractEntry、8字节结果块，以及 mp_alloc/mp_free 生命周期。保留现有三个入口及其内存协议，不增加第二种结果包络。
- 请求对象为：{contractVersion:"1.0", catalog:MenuCatalog, meal:"breakfast"|"lunch"|"dinner", offerIds:string[]}。
- offerIds 必须非空且不重复；本入口只查询单份实际售卖 Offer，不接收 quantity，也不调用推荐或求解器。
- 复用现有 ParseCatalog、ValidateCatalogSemantics、catalogHash 校验和 OfferNutrition 等路径；按请求顺序返回，与指定餐次匹配的真实可售 Offer。
- 规则套餐展开后的 Offer ID 可能包含 #、+，也可能长于普通稳定 ID。必须使用现有实际报价查找语义；不得套用普通 ID 的 64 字符校验而拒绝有效展开 Offer。
- 任一 ID 不存在或不属于该餐次的实际报价时，沿现有非法输入错误机制处理，整次调用失败，不返回部分成功结果。
- 成功业务对象为：{menuVersion,catalogHash,meal,offers:[{offerId,dishId,windowId,portionCode,nutrition:{energyKcal,proteinDg,fatDg,carbDg},nutritionComplete,estimated}]}，外层使用现有 ResultEnvelope。
- 四个营养值分别允许 null；保留已知零和部分未知。nutritionComplete 根据四项完整性生成；estimated 沿用现有来源元数据。单位沿用现有字段约定：energyKcal为整数kcal，其余营养字段为整数dg；只复用核心结果，不在新入口重复换算或舍入。
- 每项结果代表一份 Offer。整/半份缩放、override、固定套餐和规则套餐求和由已有核心函数完成。此接口不输出价格，不使用目标值或推荐结果代替菜单营养。
