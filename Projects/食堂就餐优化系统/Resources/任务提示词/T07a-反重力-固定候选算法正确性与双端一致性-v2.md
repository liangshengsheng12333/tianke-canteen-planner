- 历史关键反例入口：上述 T04 证据中的 `inputs/`、`outputs/t04-dp-quantized-cap2.response.json` 与 `outputs/t04-algo-greedy.response.json`；T04A06 的 `Resources/报告/T04A06-sol-长planKey精确比较-证据-v1/verify_long_keys.py` 和 `baseline-4097-minimal.request.json` / `baseline-4097-minimal.enumeration.json`；T04A10 的 `Resources/报告/T04A10-sol-策略排序与剪枝一致性-证据-v1/verify_ordering.py` 及其验证材料。按当前实现选择能覆盖的关键例，不机械重跑所有历史矩阵。历史响应和哈希只是旧候选证据，不得当作本次结果。

至少覆盖以下行为：

1. **小型原始菜单两层 oracle**：独立列出所有合法单餐候选，并与核心候选枚举数/内容核对；再独立穷举全天合法组合及 T01 完整排序。无截断精确搜索下 DP 和 branch-and-bound 必须与独立真值一致。Greedy 可返回次优结果，但须满足合法性并如实保留 `searchComplete=false` 与近似标记。
2. **截断及贪心反例**：覆盖 DP 状态上限触发的离散化/截断结果及其 `searchComplete`、`capsHit`、`approximations`、`flags` 标记；复核贪心局部选择可能次优，不要求其冒充全局最优。
3. **比较与剪枝边界**：选取长 `planKey` 最小反例/4095–4097 字节边界，以及策略平局排序或非叶剪枝反例，核对三个策略的最终选择及搜索完整性；有资源限制的结果不得写成精确无解或全局最优。
4. **原生/WASM 一致性**：对本次同一输入集逐一运行三个算法、对应关键反例和必要错误/限额案例；使用固定源码候选构建隔离原生 CLI，并调用 P01 指定身份的 A11 WASM。逐项比较响应状态、方案/planKey、分数、未知/估算与搜索完整性字段；相同序列化输出应比较字节/摘要，若差异仅在格式字段也须记录实际差异并说明，不得略过语义字段。

输入必须来自最终候选或明确标记的合成极小菜单；使用隔离报告目录保存新输入、独立 oracle、原生/WASM原始响应和摘要。不得覆盖历史证据，不得改动生产源码、契约、菜单、前端或生产 WASM；允许的脚本/临时二进制/夹具仅写入本卡证据目录。只运行算法正确性和双端一致性所需用例，不测性能负载、响应时间、吞吐、内存或大规模限额。
