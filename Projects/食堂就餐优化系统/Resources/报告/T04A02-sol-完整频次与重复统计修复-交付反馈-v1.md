## 4. 正确性说明

### 4.1 完整频次与重复数的同一语义

对购买项 i，定义其底层频次 `c_i(d)`：普通单品在自身 dishId 上为 1；套餐在每个组件 dishId 上为组件 count。入口已保证固定套餐组件 dishId 唯一、count 在 1..10 内；规则套餐无放回选择，展开组件也唯一。数量锁定通过重复的购买项表达。

购买项 i 内部重复对数为 `Σ_d C(c_i(d),2)`，两购买项 i、j 之间为 `Σ_d c_i(d)c_j(d)`。因此任意购买项集合 P 的重复对数是

`R(P)=Σ_i Σ_d C(c_i(d),2)+Σ_{i<j} Σ_d c_i(d)c_j(d)=Σ_d C(Σ_i c_i(d),2)`。

新增的项内、跨项、单餐和跨餐帮助函数正好实现该式，无实例容量截断，也不依赖目录顺序。DP/BnB 根重复数为零；归纳地，添加餐 C 时执行

`R(P⊕C)=R(P)+R(C)+Σ_d count_P(d)count_C(d)`，

所以每个前缀的重复数与完整频次定义一致。终端再按相同餐内/跨餐分解汇总，恰与搜索状态一致，F4 的“585 下界对 568 终端”分裂消失。

### 4.2 DP 频次支配充分性恢复

`PrefixDishCount` 通过所有已选餐的真实购买项求和，不遗漏目录第 65 项之后的菜。`SamePrefixDishCounts` 遍历 A、B 两侧所有底层 ID，对每个 ID 比较完整累计频次；两侧均未出现的 ID 频次同为零。故函数返回 true 当且仅当两前缀完整频次向量相同。相同 ID 被重复查询只增加工作量，不改变判断。

对任意同一后缀 R，上述内积公式使两前缀新增的跨餐重复数相同。这恢复了 A01 支配定理中**频次和重复数这一前提**。分类位、营养、口味、价格等其他条件继续由原比较器负责，未将相同营养误当全部状态等价，也未改 planKey 平局规则。F1/F2 尚在，因此这里只证明本卡修复的频次部分，不越界宣称整条支配判断对所有请求已安全。

### 4.3 BnB 重复数下界恢复可采纳

后缀每餐内部最小重复数现在也是完整 `R(C)`。任意真实后缀 X 的终端重复数包括：前缀内部、每餐内部、前缀与后缀跨餐、后缀各餐之间跨餐。后两类均非负，因此

`R(P⊕X) ≥ R(P)+Σ_remaining_meals min_C R(C)`。

源码原有 `lbRepeated` 恰取右侧。本卡让该右侧与实际终端评分使用相同完整语义，消除 F4 对该不等式的反例。乐观界的其他指标及其词典序顺序未改；尤其 F2 的价格完整位问题仍影响 BnB 全局可采纳性声明。

### 4.4 计数宽度与溢出界

现有合法输入已经约束：最多 3 个不同规划餐次；每餐购买项总数至多 8；锁定数量也计入这 8 项（当前 964–969）；单个固定套餐内同一 dish 组件唯一、count≤10。规则套餐同一 dish 只取一次。因此同一底层 dish 的每餐频次≤80、全天频次≤240。本卡使用 i64 查询、内积和累加，不依赖 u8 存储。

**对 A01 未测缺口的澄清：** A01 把“u8 可能回绕”列为待证明边界，并未实测。此次结合总锁定购买项限制证明，在当前已接受的三餐/8 项/count≤10 范围内，单品频次不可能超过 240，不能把 >255 当作合法反例。原已复现 F3 是覆盖 ID 不全，F4 是统计截断，均不依赖 u8 回绕。这里给出的是新证明，不回改 A01 历史材料。

对总重复数，设底层不同 dish 数为 D，则 `R≤D×C(240,2)=D×28680`。C ABI `mp_plan` 的输入长度为 uint32（`core/include/mp/api.h`），每个不同有效 dishId 至少占一个输入字节，所以 `D<2^32`；又 `28680<2^15`，故总重复数 `<2^47`，既在 i64 范围内，也低于 JSON 2^53 精确整数上限。各中间项非负且都是最终配对集合的子集，不会先溢出再抵消。此证明不新增输入上限、不缩小已批准范围；其他营养/价格运算仍按原实现，本卡不替它们作全域证明。
