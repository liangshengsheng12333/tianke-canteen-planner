## 1. 问题：不是换皮，是“每页都像设置页”

现状量化（从 WXML 数出来，不是感觉）：

| 页面 | 首屏按钮数（WXML） | 行数 | 卡片数 | 主要问题 |
|---|---|---|---|---|
| 今日 home | 15（渲染后约 18：每餐 4 个操作 × 3 餐） | 15 | 7 | 每餐平铺「锁定/售罄/解除/换菜」；已入菜单、档案、方案、主推荐全在一屏 |
| 记餐 logs | 12 | 14 | 2 | 确认已吃、编辑、撤销、补记、结束餐次全平铺 |
| 菜单 menu | 11 | 28 | 4 | 导入/导出/恢复三区全展开；版本号、catalogHash、预检阶段、差异明细直接暴露 |
| 我的 profile | 5 | 12 | 4 | 12 个字段平铺，手动营养目标（能量/蛋白/脂肪/碳水/来源）与基础资料混在一起 |
| 开发 dev | 14 | 9 | 7 | 诊断页占了正式 tab，主流程被技术内容稀释 |

结构性问题：
1. 底部导航是每个页面自己画一份（5 页 × 1 份），不像原生小程序；
2. 开发页占 tab，正式用户会点进“设置很多”的页面；
3. 技术术语（catalogHash、sha256、OkPartial、预检阶段、原子替换）出现在首屏；
4. 没有信息分级：所有操作同一视觉权重，用户不知道“先点哪个”。

## 2. 目标与非目标

目标（可验收）：
- 每个主页面**首屏可见按钮 ≤ 3**（主操作 1 + 次操作 1 + 「更多」1）；
- 首屏不出现技术术语，全部收进「高级信息」；
- 主流程点击次数：看方案 0 次额外点击（进页面即见）、记餐 ≤ 3 次、导入菜单 ≤ 4 次、恢复备份 ≤ 4 次；
- 视觉统一：白底浅灰背景、橙色主色、大圆角卡片、原生 tabBar，和系统设置类 App 观感一致。

非目标（本次不做）：
- 不改任何业务规则、核心算法、数据模型、契约版本；不动 `core/`、`tools/core/`、WASM；
- 不引入第三方 UI 库（继续零依赖）；
- 不做发布/上传/体验版；
- 不新增业务功能（如社交、推荐、账户）。

## 4. 信息架构（4 tab）

```
今日 ── 状态一行 + 三餐方案摘要 + 主按钮（重新生成方案）+ 去记餐
 │        └─ 每餐「…」：锁定 / 标记售罄 / 解除售罄 / 换菜 / 详情
记餐 ── 日期行 + 三餐卡片（确认已吃）+ 已记摘要「…」（编辑/撤销/补记/结束）
菜单 ── ① 导入菜单  ② 导出备份  ③ 恢复备份   + 高级信息（折叠）
我的 ── 档案表单（6 项必填）+ 保存 + 高级设置（折叠）+ 菜单与数据 + 诊断（开发者）
```

每个页面的“更多/高级信息”都用同一个折叠组件样式：一行标题 + 右侧「展开/收起」，展开后显示原内容。

## 5. 逐页方案（含线框）

### 5.1 今日
```
┌──────────────────────────────┐
│ 今日                    ⋯    │  ← 右上「…」= 页面级更多（档案摘要/已入菜单提醒）
│ 10月20日 周二 · 已记 1 餐      │
├──────────────────────────────┤
│ 今日方案        [有 2 项限制]  │  ← 限制标记保留一行，详情折叠
│  早  一楼·包子套餐   ¥6.5   › │
│  午  二楼·鸡腿饭     ¥13    › │
│  晚  未生成             ›     │
│  [   重新生成方案   ]         │  ← 唯一主按钮
│  [      去记餐      ]         │  ← 次按钮
└──────────────────────────────┘
点每餐「›」→ 展开该餐详情（菜品/价格/营养/限制原因/锁定/售罄/换菜）
```
- 保留：三餐摘要、主按钮、去记餐、限制标记一行。
- 折叠：「…」→ 档案摘要、已入菜单提醒、方案版本/时间（原首页上半部分内容）。
- 移除出首屏：每餐 4 个操作按钮（移入每餐详情）。
- 空态：`还没有档案` → 一句话 + 「去建档」。

### 5.2 记餐

```
│ 记餐                    ⋯    │  ← 页面级更多（近 7 天、导出？不新增）

├──────────────────────────────┤
│ 早餐   未记录                 │
│    [ 确认已吃 ]               │
├──────────────────────────────┤
│ 午餐   已记录 · 1 项货品   ⋯  │  ← 「…」：编辑 / 撤销 / 补记 / 结束餐次

├──────────────────────────────┤
│ 晚餐   未记录                 │
│    [ 确认已吃 ]               │
└──────────────────────────────┘
```

- 折叠：编辑表单（点「…→编辑」才展开）、撤销、补记、结束餐次。
- 移除出首屏：「补记食物」的 8+ 字段表单（改为弹层/折叠区）、近 7 天（「…」里）。

### 5.3 菜单
```
┌──────────────────────────────┐
│ 菜单                          │
├──────────────────────────────┤
│ ① 导入菜单                    │
│   当前：模拟食堂 · 2 窗口 4 菜 │
│   [ 选择文件… ]  [ 预检 ]     │
│   ✓ 可以替换                   │  ← 人话结果；✗ 时显示原因一行
│   [ 确认替换菜单 ]（仅预检通过时出现，危险色）│
├──────────────────────────────┤
│ ② 导出备份                    │
│   上次：10月20日 22:26 · 9,466 字 │
│   [ 导出备份 ]  [ 分享文件 ]  │
├──────────────────────────────┤
│ ③ 恢复备份                    │
│   [ 选择文件… ]  [ 预检 ]  [ 确认恢复 ]│
│   ✓ 摘要一致，可以恢复         │
├──────────────────────────────┤
│ 高级信息                    ⌄ │  ← 折叠
│   菜单版本 / catalogHash /     │
│   预检阶段 / 差异明细 / 原始 JSON│
└──────────────────────────────┘
```
- 保留：三个步骤卡、三组主操作、人话预检结果。
- 折叠：版本号、catalogHash、预检阶段、差异明细、文件摘要、粘贴 JSON、复制到剪贴板、原始文本。
- 移除：首屏“文件名（用于记录来源）”输入框默认隐藏（自动取文件名，可在高级信息里改）。
- 危险操作：「确认替换」「确认恢复」二次确认（保留现有原子性，不改逻辑）。

## 6. 文案：术语 → 人话

| 现在（首屏可见） | 改后（首屏） | 保留位置 |
|---|---|---|
| `catalogHash sha256:…` | 菜单指纹 | 高级信息 |
| 菜单版本 `menu-…-b` | 当前菜单：模拟食堂 · 2 窗口 4 菜 | 高级信息 |
| 预检阶段 `parse/ready` | ✓ 可以替换 / ✗ 文件格式不对 | 高级信息 |
| `OkPartial`、原子替换、规范化序列化 | 不出现 | 高级信息/报告 |
| `dp/branchAndBound`、`comboRules` | 不出现 | 高级信息 |
| 恢复摘要 sha256 对比 | ✓ 摘要一致，可以恢复 | 高级信息 |

错误文案统一模板：`一句话原因 + 下一步动作`（例：`文件格式不对，请选择导出的备份文件`）。

## 7. 交互规范

- 折叠：同一时间每页只展开一个「高级信息」；展开状态不持久化（离开页面重置）。
- 加载：按钮原地显示「处理中…」并禁用，不做全屏 loading。
- 空态：一行说明 + 一个主按钮。
- 危险操作（替换菜单/恢复/撤销记餐/解除全部）：二次确认，确认按钮用危险色。
- Toast 只用于成功/失败一句话，技术细节留在页面状态行。
- 触控目标 ≥ 88rpx 高；tabBar 用原生，避免自绘点击区问题。
