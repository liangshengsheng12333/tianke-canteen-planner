## 四、客观优点（实际可见）

- **测试状态透明且贯穿始终**：首页黄条"示例菜单"、自选页"当前为模拟菜单（非真实供应）"、"查看说明"弹窗明确"价格与营养均为开发用占量，不构成真实产品承诺或收银信息"，各页口径一致，很难误当成真实数据。
- **记录改撤链路完整可逆**：补记 → 修改（修订号递增）→ 撤销，历史保留"已被修改替代/已撤销"痕迹，确认弹窗拦截，状态即时刷新；"实付未填/营养未知"用醒目标签与黄色提示表达，"未知值不按 0 计算"口径清楚。
- **确认反馈指向明确**：确认吃了后不仅告知"已计入午餐"，还给出"记录会出现在今日和记录/月历里；如需修改……请到记录页改记或撤销"及直达入口，新手能找到下一步。
- **模式与主题切换即时生效**：简易/完整由右上胶囊原地切换、内容差异（蛋白质/脂肪/碳水明细行）直观；深色模式在首页、自选、记录页整体一致（例外见建议 2）。
- **月历集成自然**：记录页内展开，月份切换流畅，过去日期自动只读，避免误改历史。
- **自选页草稿声明清楚**："勾选和数量在确认前都只是草稿"、"至少选 1 项才能确认吃了"，禁用态与提示相互对应。

## 五、建议清单（共 7 条，按优先级排列）

### 1. 本餐详情内"换菜"点击后无任何反馈（同弹层"锁定"正常）｜可用性缺陷｜优先级：高｜成本：低

- **复现**：首页（有方案态）→"这餐详情›"→ 菜品卡"清蒸鸡胸"→ 点"换菜"。三次点击（即时/0.35s/3s 截图：24-点换菜后-*.png），均无选择面板、无 toast、无状态变化；数据层菜品未变。
- **对照**：同一弹层内"锁定"按钮点击立即生效（25-点锁定后.png），说明按钮事件可达，"换菜"链路单独静默失败。
- **影响**：换菜是本产品核心闭环之一；用户点了没反应会认为功能坏了，且无从得知下一步。
- **静态核对（实操后另列）**：`pages/home/index.ts` 的 `onSwapItem → pickOfferAndSwap → chooseIndex` 使用 `wx.showActionSheet`，其 `fail` 分支静默 `resolve(null)` 直接返回，无任何用户提示；候选较多时的提示 toast 只在 labels>6 才触发。**推测**模拟器环境下 showActionSheet 调用失败（如 `alertText` 兼容性）落入该静默分支；根因未在真机验证，标注为推测。餐次级"换一份"走同一 `chooseIndex` 路径，**推测**受同样影响（未单独实测）。
- **建议改法**：showActionSheet 失败或取消时给出兜底反馈（如"未能打开选择面板"toast），或改用页内自绘选择列表，不依赖原生 ActionSheet；成功/失败路径都应有可见结果。

### 2. "我的"页深色模式下顶部导航栏仍为白底黑字｜可用性缺陷｜优先级：中｜成本：低

- **复现**：我的页 →"显示与外观"→ 点"深色"。内容区、卡片、底栏全部变深，但顶部导航栏保持白底黑字（12-我的-深色.png、33-我的-深色复核.png 两次复现）。同条件下首页、自选页、记录页导航栏均正确变深（30/31/34-*.png）。
- **影响**：同一操作后不同页面的导航表现不一致，深色下顶部出现突兀亮条，显得"没切完"。
- **建议改法**：主题切换时对该页同步调用 `wx.setNavigationBarColor`（或在页面配置/主题监听中补齐），与其他页面对齐。

### 3. 开发者技术词汇直接暴露给普通用户｜可用性缺陷（文案）｜优先级：中｜成本：低

- **复现/现象**：
  - 首页"其他方案"卡内橙红字"当前受支持子集：greedy + comboRules=[]"（02-首页-底部.png）；
  - 个人资料页 hero"用于计算营养目标；BMI、能量与宏量目标由 C++ WASM 计算，本页不自行套公式"，按钮"计算目标（WASM）"，以及"营养目标 (WASM)""BMI (WASM)"（18/19c-*.png）；
  - 数据管理页"菜单版本 menu-simulated-v2"（32-数据管理.png，此处位于技术信息附近，尚可接受）。
- **影响**：普通操作员无法理解"WASM/greedy/comboRules"，既不产生信任也不提供可执行信息；首页该红字还占用"其他方案"卡的显著位置。
- **建议改法**：面向用户改为人话（如"由本机内置引擎计算，不联网"）；算法/子集等细节收敛到"更多外观说明/技术信息"类次级入口。注意：技术口径本身在开发语境有用，不必删除，建议仅调整露出层级。

### 4. 首页"其他方案"卡说明文字堆叠重复｜可用性缺陷（信息层级）｜优先级：中｜成本：低

- **复现**：生成方案后首页滚至"其他方案"卡（22-首页方案-滚动.png）。同一卡内出现 4 段含义相近的文字："方案已就绪；可切换主选/备选……""已生成方案，但存在独立限制标志（如估算数据、价格/营养不完整、近似结果），请查看标志说明。""上次运行：方案 已选类型 (OkPartial)"、徽标"含估算数据"，另有绿色按钮"重新生成方案"。
- **影响**：用户要读四段话才知道一件事："方案有了，但部分数据是估算"；首屏下方信息密度大，重点（可切换、可重生成）被淹没。
- **建议改法**：合并为一行状态 + 一个可展开的"为什么有标志？";"OkPartial"等内部状态名不外露。与建议 3 同源，可一并处理。

### 5. 自选页底部固定栏不显示已选与合计｜可用性缺陷｜优先级：中｜成本：低

- **复现**：首页"自己选菜"→ 点选任一菜品 → 停留首屏。已知合计（¥8.00）与已选清单位于页面中部"将记录的内容"卡，底部固定栏只有"取消/确认吃了"（03/04-*.png）。
- **影响**：选完菜后，最需要确认的"选了什么、多少钱"不在视线内；多选几项后用户需来回滚动核对，也容易漏看金额变化。
- **建议改法**：底部固定栏常显"已选 n 项 · 合计 ¥x"，点击可滚到明细；不改变现有确认逻辑。

### 6. "这餐的营养"百分比缺少含义说明｜可用性缺陷（轻）｜优先级：低｜成本：低

- **复现**：生成方案后首页，"这餐的营养"行显示"蛋白质 37.6 克 30.0% / 脂肪 4.5 克 8.1% / 碳水 77.4 克 61.9%"（21-生成方案后.png）。
- **现象/影响**：百分比未标注参照物（实测对照档案"每日目标"可推得是占每日目标比例），普通用户可能误读为"菜品成分占比"或"每份营养占比"。
- **建议改法**：区块标题或列头加四个字，如"占每日目标"；或在"约 513 千卡"行同样补百分比口径。

### 7. 资料未保存时显示预填默认值，易被误读为"已填好"｜可用性缺陷（轻）｜优先级：低｜成本：低

- **复现**：首次进入我的页（保存前）："当前目标"卡显示"资料未保存 / 还没有保存个人资料"，而紧随其后的"个人资料"卡已展示 男 / 20 岁 / 175.0 cm / 70.0 kg 等值（11-我的.png）。
- **影响**：两种信号并存，新用户可能以为已经填好无需保存，或不知道显示的是默认值还是自己之前的输入。
- **建议改法**：在个人资料卡加一行小字"当前为默认值，保存后才用于计算目标"；或将未保存时的字段显示为占位样式。
