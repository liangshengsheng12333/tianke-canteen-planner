# 天科食客双模式与视觉改版｜简要 PRD 草案

版本 v1｜2026-10-20 Asia/Shanghai  
**状态：待用户确认；未授权编码或派发外部。** 本文是讨论草案。除“保留现有业务能力，并希望在设置内切换简易/完整模式”外，以下默认值、导航和实现顺序均是 P01 建议，尚未视为用户批准。

## 问题

用户反馈：当前 T05 整体 UI 显得臃肿，技术和维护功能偏多，字体层级密集；用户喜欢现有功能，希望设置内可自由切换简易/完整模式，并参考最新小米系统的磨砂玻璃风格。

结合 DSH 当前页面反馈，主页把档案摘要、计划状态、重复提示、营养目标与预算明细、逐菜操作集中呈现；五页导航中也有面向开发的入口。改版目标是重组信息层级，保留现有业务能力和数据，不再往旧布局上堆叠新功能。

## 成功标准（建议，待确认）

- 简易首页先呈现今日餐次、菜名、窗口和价格，并突出一个主要动作；营养进度以摘要呈现，详细操作可进入对应详情。
- 完整模式保留详细营养、预算和高级选餐信息，并通过留白与清晰分组维持可读性。
- 原有业务能力均能在完整模式或设置中的高级入口找到。
- 两种模式共用同一程序、数据和计算核心；切换不清空档案、菜单、计划、日志、锁定或售罄状态，同一输入仍使用相同核心结果；未保存表单不因切换丢失。
- 超预算、未知营养/估算、目标不可用等重要提示在两种模式下均可见，不能为了简洁而隐藏。
- 微信实际渲染和滚动表现可验证；没有兼容性证据时，不承诺与系统界面完全相同的玻璃效果。

## 范围（建议，待确认）

- 在“我的 → 设置”提供“界面模式：简易/完整”，建议默认简易并记住用户选择。
- 建议底部导航调整为“今日 / 记录 / 我的”。简易模式的餐卡突出“确认 / 换一份”，其余操作放入详情；完整模式保留详细营养、预算与高级选餐。
- 菜单维护、导入、导出和备份建议集中到“我的 / 设置 / 高级功能”。开发诊断入口不常驻大众导航；不由此增加后台服务或角色权限。
- 先产出简易首页、完整首页、设置三个可运行设计预览，标为设计候选；获得视觉反馈后再统一页面并回归业务。

## 视觉方向（建议，待确认）

- 参考小米官方页面所述的 HyperOS 4“柔光玻璃”、淡色空间和圆润层次。少量玻璃材质可用于底部导航、顶栏或弹层；菜品正文卡优先使用实底，保证阅读。
- 避免全屏多层模糊、密集描边和过小标签。字体以稳定的系统无衬线为主；MiSans 仅作为清晰字形参考。若后续决定实际嵌入字体，须先阅读官方许可并保留声明；本阶段不下载字体、不新增依赖。
- 优先通过菜名/价格/正文/辅助信息的字号、字重、颜色和留白建立层级，再使用材质和动效；对比度不能降低，动效不能压过内容。
- 可以用轻量半透明表达层次，不承诺微信中实现系统级玻璃表现。

## 约束

- 复用 DSH 已交付的 T05 v2 页面/数据实现和固定 T02 v2 WASM；仅重做呈现，不重写正式营养算法或计划核心。
- 不改反重力 T04 的目录，不读取或接入其未验收的新产物；与 T04 保持目录分离。
- 不删除既有功能、档案或历史记录；不把尚未完成的红米真机测试写成通过。
- 真实菜单仍由 T03 提供并验收；它不阻塞使用明确标记的模拟菜单讨论或开发。
- T05 v2 的第 1—4 项已由 DSH 报告完成并冻结候选、编译和新预览码；第 5 项红米真机仍待用户配合。任务交回不等于红米测试完成。
- 当前仅形成草案，不构成编码、提示词撰写、外部派单或转交授权。
