## 路线原则

**先完成 → 接合 → 固定候选 → 集中测试 → 缺陷修复与复测 → 独立审查交付。**  
正式全流程测试集中在最终待测候选上，避免测试后因新增功能或视觉调整反复换候选。作者必要编译、局部快速自查和开发阶段已有测试继续进行；“集中测试”不等于盲目连续改动，也不降低各任务卡或 A01—A12 验收要求。

### 2. 后续阶段（当前暂停）：阶段交付后技术接合

只有 UI 预览经用户审阅、P01 明确发出后续实施/核心任务并形成所需阶段交付后，才恢复本步骤。届时由 P01 选定**唯一**集成候选；DSH 负责前端请求迁移与新 WASM 接入，反重力继续维护 `core/`，不得同时写入同一目录。

接入时必须把旧 T02 短 `limits` 字段迁移到 T01 冻结的规范 `limits`，并将新请求口径与新二进制绑定；只替换 WASM 文件不算完成迁移。真实菜单到位后纳入 T06。菜单仍缺时，只能记录为明确标注模拟数据的技术接合，不得登记 T03 或真实菜单 T06 完成。

营养比例展示需先统一数据来源和计算口径：不得把全天目标 `composition` 当成本餐供能比例，也不得捏造健康分数。

### 3. 固定待测候选

业务功能、界面、核心/接口和菜单范围收口后，固定一个待测候选，并记录源码、配置和产物哈希；暂停新增功能及非必要风格调整。此步骤只建立正式测试基线，**不等于 T10b 最终归档冻结**。

### 4. 对同一候选集中执行正式测试

按任务依赖顺序进行，均针对同一固定候选：

1. **T06：**全流程、预算、未知营养、锁定/售罄、跨日、导入/恢复和异常矩阵。
2. **T07：**三算法双层参照、Native/WASM 一致性、零 warning、注释门槛、异常与正式内存检查、规模和性能实验；冻结进入 T08 所需的性能配置。
3. **T08：**红米完整流程、离线、系统级退出/杀进程恢复、冷启动与热运行，以及实际朋友试用。工具或 Node 结果不能代替真机；朋友反馈不自动代用户发送。自动业务/算法检查可在无写代码的固定候选上并行，T08 正式性能验收依赖 T07 性能配置。

### 5. 必要缺陷修复与受影响复测

汇总必要缺陷后统一修复。修复会产生新候选，应更新身份并只重测受影响项目和关键主流程。测试期间不穿插新增功能或随意改 UI；保留旧失败记录，不放宽验收要求。

### 6. 审前材料、独立总审与最终冻结

1. **T10a：**准备同候选材料、运行入口、约五分钟演示和现场条件；材料框架与过程素材可提前积累，正式截图和实验表以最终候选为准。
2. **T09：**由 P09 按请求配置 gpt-6-luna / High 独立总审。实际平台信息仍据可核实证据记录。
3. **T10b：**仅在独立总审通过后做最终冻结归档。顺序不得颠倒。
