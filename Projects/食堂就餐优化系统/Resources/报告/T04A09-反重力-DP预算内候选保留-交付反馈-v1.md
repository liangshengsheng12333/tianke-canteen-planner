## 三、代码靶向修正与生产哈希变更

主执行员作为唯一核心写入者，对 `core/src/planner.cpp` 进行了精准的最小算法改动与理论注释纠偏：

### 3.1 具体修改清单

1. **DP 预算内见证生成与初始择优注入 (`RunDpAlgorithm`)**：
   - **实施位置**：`RunDpAlgorithm` 中终端 `bestForStrategy` 初始化后、原 `currentLayer` 终端遍历前。
   - **门禁守卫**：
     ```cpp
     if (dpCapTriggered && config.hasBudget && intake.priceComplete &&
         intake.knownPriceCents <= config.budgetCents)
     ```
   - **扫描与决策**：线性扫描 $M \le 3$ 餐的已生成合法候选池 `mealSets[m].candidates`，为每餐选出 `cand.priceComplete == true` 且 `knownPriceCents` 最低的首个候选（严格小于号 `<` 实现确定性首选平局决裁）。
   - **预算核验与评估**：若各餐均选出且待选总价 $\le B - S$，拼装 `witnessPlan`，调用既有 `EvaluateFullDayPlan` 进行唯一一次完整评估。
   - **非强制替换**：若 `witnessPlan.viable`，先将其载入各策略候选 `bestForStrategy[s]`；随后原 `currentLayer` 循环如常遍历，任何更优解通过已有 `IsPlanBetterForStrategy` 比较器自然覆盖，绝不强制取代 DP 已有的更优预算内方案。
2. **F5 理论误差注释纠偏**：
   - 彻底纠正了原注释中“终端累计量化误差上界公式”声称的全局有效性；
   - 明确指出：该误差界仅在局部桶内替换且代表路径未被丢弃时成立；一旦状态数超过 `maxDpStates` 导致整桶被丢弃，算法转为启发式近似，无全局统一度量界（与 A01 3999bp 反例相印证）；
   - 澄清本次见证仅保障已生成候选池内的预算可行性，不升级为原菜单全局最优。
