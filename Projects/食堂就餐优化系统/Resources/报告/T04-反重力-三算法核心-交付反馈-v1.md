## 二、层一（Layer 1）合法单餐候选生成器与套餐展开设计

### 2.1 固定套餐（`dish.kind == "combo"`）与规则套餐（`catalog.comboRules[]`）
1. **固定套餐校验与营养推导**（[`ValidateCatalogSemantics`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/catalog.cpp#L1185-L1275)）：
   - 校验 `dish.components[]` 非空、每个子组件 `dishId` 在 `catalog.dishes` 中存在且必须为 `kind == "single"`（严禁套餐嵌套）、`count` 为正整数且同一套餐内组件 `dishId` 不重复。
   - 若固定套餐自身未直接提供完整四项营养素，则当且仅当所有子组件对应营养素均已知（`has*=true`）时按 $\sum \text{nutrition}_i \times \text{count}_i$ 汇总；任一组件含未知营养素则保持 `has*=false`（绝不把 `null` 当 `0`）；任一组件 `estimated == true` 则传播 `estimated = true`。
2. **规则套餐确定性展开**（[`ExpandAllComboRules`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/catalog.cpp#L415-L625)）：
   - 校验 `ruleId`、`name`、`windowId`、`mealWindows`、`totalPriceCents`、`includesRice`、`requiredCounts`（分类键白名单与组件总数 $1\dots 8$）、`candidateDishIds`（存在且均为 `single`）、`nutritionPolicy == "sumComponents"`。
   - 对每个供应餐次 `mealBit`，过滤在该窗口与餐次合法供应的候选单品，按分类分组并对每组单品按 `dishId` UTF-8 字节序升序排列，递归生成满足 `requiredCounts` 的组合。
   - 展开后的合成报价稳定 ID 严格遵循契约格式：
     $$\text{offerId} = \text{ruleId} \mathbin{\Vert} \text{"\#"} \mathbin{\Vert} \text{join}(\text{sort}(\text{componentDishIds}), \text{"+"})$$
     例如：`rule-lunch-set#dish-chicken+dish-pork`。
   - 展开后的合成 `OfferRecord` 存入 `catalog.expandedComboOffers`，与静态 `catalog.offers` 同等参与 `itemLocks` 锁定、`soldOut` 连带售罄过滤（任一底层组件单品售罄则该套餐连带不可选）及单餐候选枚举。

### 2.2 层一合法单餐候选枚举（[`EnumerateMealCandidates`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L915-L1085)）
- **共用入口**：`greedy`、`dp`、`branchAndBound` 在进入各自搜索前，统一调用 `EnumerateMealCandidates` 生成每餐合法单餐候选集 `MealCandidateSet`。
- **单餐合法性与相容性不变量**：
  1. **同窗约束**：同一单餐候选内的所有项目必须来自同一个 `windowId`，且满足 `windowLocks` 与 `itemLocks` 所在窗口一致性；
  2. **含米饭互斥**（[`IsOfferCompatibleWithMealItems`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L720-L750)）：若餐次内已选含饭套餐（`riceIncluded == true`），禁止再选独立米饭（`riceDish == true`）或第二个含饭套餐；反之亦然；
  3. **套餐组件不重复**：若已选项或待选项包含套餐（`isCombo == true`），其底层单品组件集合不得与餐内其他项发生单品重叠；
  4. **未知营养过滤**：未锁定的未知营养报价（`!nut.Complete()`）不进入自动新增池；被 `itemLocks` 强制锁定的未知营养报价允许入餐并打标 `LOCKED_UNKNOWN_NUTRITION` 与 `NUTRITION_INCOMPLETE`；
  5. **候选上限截断**：按窗口及 `offerId` 升序枚举 $1 \dots \text{maxItemsPerMeal}$ 子集；若枚举数超出 `limits.maxMealCandidatesPerMeal`，立即截断并向 `result.search` 写入 `capsHit(maxMealCandidatesPerMeal)` 与 `approximations(APPROXIMATE_CANDIDATES)`。

## 三、三套手写算法设计、数学证明与复杂度分析

### 3.1 算法一：`greedy`（逐餐每窗边际增益贪心，[`RunGreedyAlgorithm`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L1680-L1790)）
- **核心机制**：
  - 在每一餐的每个合法窗口内，从包含必选锁定项的最小基础候选出发，每步迭代挑选 1 个相容且使当前单餐参考目标营养偏差 `DeviationBp(mealRef, sums)` 下降最多的报价（[`BuildWindowGreedyMealPlans`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L1460-L1615)），直至达到 `maxItemsPerMeal` 或无正边际收益；若启用预算，同步按餐次参考能量占比构造预算受限单餐候选。
  - 在各餐生成的窗口代表方案小集合上组合评估各策略最优解。
- **诚实性声明**：
  - 因贪心仅作单餐局部边际决策、未遍历全天跨餐笛卡尔积空间，`result.search.searchComplete` 恒为 `false`，且 `result.search.approximations` 恒记录 `APPROXIMATE_CANDIDATES`（`scope="allMeals"`）；`statesEvaluated = null`，`nodesEvaluated` 精确记录评估步数。

### 3.2 算法二：`dp`（多阶段动态规划、精确支配定理与受限桶化离散化，[`RunDpAlgorithm`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L2040-L2295)）
- **阶段与状态定义**：
  - 阶段 $t \in \{1 \dots M\}$（$M = |\text{planningMeals}| \le 3$）。
  - 状态向量 $S_t$（[`DpState`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L1800-L1815)）记录前 $t$ 餐前缀选择索引 `mealChoiceIdx[0..t-1]`、累计四项营养素 $(E, P, F, C)$、营养完整位 `nutComplete`、价格完整位 `priceComplete`、累计已知价格 `knownPriceCents`、已知分类覆盖位掩码 `catMask`、累计未知分类数 `unknownCatCount`、累计重复菜对数 `repeatedPairCount`、累计口味分 `prefScore` 以及底层单品频次向量 $\vec{d} \in \mathbb{N}^{64}$。
- **精确等价支配定理（Exact Dominance Theorem，[`DpExactDominates`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L1940-L2020)）**：
  - **非终端阶段（$t < M$）**：若同阶段两状态 $A, B$ 满足 $(E_A, P_A, F_A, C_A) = (E_B, P_B, F_B, C_B)$、`nutComplete` 与 `priceComplete` 相同、`catMask` 相同且单品频次向量 $\vec{d}_A = \vec{d}_B$，则对任意后续餐次后缀 $R$，$A \oplus R$ 与 $B \oplus R$ 的终端营养偏差、分档、类别覆盖数、后续新增重复菜对数均恒等。若此时 $A$ 在 `(knownPriceCents, repeatedPairCount, unknownCatCount)` 上均 $\le B$、在 `prefScore` 上 $\ge B$ 且至少一项严格更优，则对 `primary` / `economy` / `taste` 任意策略，$A \oplus R$ 恒严格优于 $B \oplus R$，剪除 $B$ **100% 数学无损**。
  - **终端阶段（$t = M$）**：不再有后续餐次转移，此时仅终端评价指标（四项营养总和、完整性、已知价格、重复菜对数、分类覆盖数 $\text{ popcount}(\text{catMask})$、未知分类数、口味分）参与比较；若两终端状态在上述指标上完全打平，则直接通过栈上规范元组 SHA-256 比较器 [`CompareTerminalDpPlanKey`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L1915-L1935) 按契约 §10.4 的 `planKey` 升序决胜，从而保证无截断时与全天穷举 100% 恒等。
- **受限桶化离散化与量化误差上界证明**：
  - 当某阶段精确非支配状态数超过 `limits.maxDpStates` 时，启用步长为 $(\Delta_E, \Delta_P, \Delta_F, \Delta_C) = (20\text{ kcal}, 50\text{ dg}, 50\text{ dg}, 50\text{ dg})$ 的营养网格桶化，并在桶内保留启发式评分最优代表元，最后按 `maxDpStates` 截断：
    - 单阶段桶化在各营养素维度引入的最大绝对误差 $\le \Delta_n$，$M$ 阶段累计误差 $\delta_n \le M \cdot \Delta_n$；
    - 由三角不等式 $||x - T_n| - |x' - T_n|| \le |x - x'| \le \delta_n$，终端 `nutritionDeviationBp` 的最大偏差损失上界为：
      $$\Delta \text{dev}_{\max} \le \sum_{n \in \{E,P,F,C\}} \operatorname{round\_half\_up}\!\left(\frac{10000 \cdot w_n \cdot M \cdot \Delta_n}{1000 \cdot T_n}\right)$$
  - 一旦触发 `maxDpStates`，`result.search` 必记录 `capsHit(maxDpStates)`、`approximations(APPROXIMATE_DISCRETIZATION)` 且置 `searchComplete = false`，对应方案 `flags` 打标 `APPROXIMATE_DISCRETIZATION` 与 `SEARCH_LIMIT_REACHED`。

### 3.3 算法三：`branchAndBound`（深度优先分支限界与可证明乐观下界剪枝，[`RunBranchAndBoundAlgorithm`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L2885-L2990)）
- **后缀极值预处理（[`ComputeSuffixBounds`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L2515-L2605)）**：
  - 对剩余餐次集合 $R = \{d+1 \dots M\}$，预先计算四项营养素可达闭区间 $[E_R^{\min}, E_R^{\max}], \dots, [C_R^{\min}, C_R^{\max}]$、最小已知价格增量 $p_R^{\min}$、最大口味增量 $\text{pref}_R^{\max}$、分类位掩码并集 $\text{mask}_R^{\cup}$、单餐内部最少重复对数之和 $\text{rep}_R^{\min}$ 与最少未知分类数之和 $\text{unk}_R^{\min}$。
- **可采纳乐观界（Admissible Bounds）与不漏最优解证明（[`CanPruneForStrategy`](file:///d:/项目/cpp/Projects/食堂就餐优化系统/core/src/planner.cpp#L2615-L2765)）**：
  - 对当前前缀状态 $P$ 与剩余后缀界 $R$，任意完整延伸方案 $X \in \text{Subtree}(P)$ 的终端营养素 $n(X)$ 必落在 $[n(P) + n_R^{\min},\ n(P) + n_R^{\max}]$ 内。因此点到区间的最短距离：
    $$d_n^{\min}(P) = \operatorname{dist}\!\big(T_n,\ [n(P)+n_R^{\min},\ n(P)+n_R^{\max}]\big) \le |n(X) - T_n|$$
    代入 `WeightedTerm` 得到可采纳偏差下界 $\underline{\text{dev}}(P) \le \text{dev}(X)$ 与分档下界 $\underline{\text{tier}}(P) = \lfloor \underline{\text{dev}}(P) / W_{\text{tier}} \rfloor \le \text{tier}(X)$。
  - 同时满足：价格下界 $\underline{\text{price}}(P) = \text{price}(P) + p_R^{\min} \le \text{price}(X)$、口味上界 $\overline{\text{pref}}(P) = \text{pref}(P) + \text{pref}_R^{\max} \ge \text{pref}(X)$、类别覆盖上界 $\overline{\text{cov}}(P) = \text{popcount}(\text{mask}(P) \cup \text{mask}_R^{\cup}) \ge \text{cov}(X)$、重复菜对数下界 $\underline{\text{rep}}(P) = \text{rep}(P) + \text{rep}_R^{\min} \le \text{rep}(X)$（因为跨餐重菜对数 $\ge 0$）。
  - **剪枝安全条件**：仅当子树构成的理想乐观向量 $\text{Opt}(P)$ 在全部请求策略下均**严格劣于**当前已找到的完整可行解 `incumbent[s]`（平局时绝不剪枝，保留至叶子比较 `planKey`）时才剪除该分支，故在不触发限额时**数学上 100% 保证不漏全局最优解**。
- **启发式分支排序**：在每层递归前按前缀接近餐次参考目标的启发式得分升序排列子节点，使优质 `incumbent` 尽早建立，在场景 A（总空间 24,696 组合）下仅评估 **6,692** 个节点即完成全局最优性证明（剪枝率 **72.9%**）。
