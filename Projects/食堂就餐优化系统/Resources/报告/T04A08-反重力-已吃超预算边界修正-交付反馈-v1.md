## 三、代码靶向修正与生产哈希变更

主执行员作为唯一核心写入者，对 `core/src/planner.cpp` 进行了极简的靶向修正，彻底消除了负剩余预算预先夹零导致的边界倒错：

### 3.1 具体修改清单

1. **终端超预算判定 (`EvaluateFullDayPlan`)**：
   - **原缺陷**：先计算 `remainingBudget = max(0, budgetCents - intake.knownPriceCents)`，再以 `plan->knownPriceCents > remainingBudget` 判定。当 $S=101, P=0, B=100$ 时，$P > 0$（`0 > 0`）为 `false`，导致误判预算内。
   - **修正**：直接按实际已知总支出比较：
     ```cpp
     plan->overBudget = config.hasBudget &&
                        (!plan->priceComplete || !intake.priceComplete ||
                         (plan->knownPriceCents + intake.knownPriceCents > config.budgetCents));
     ```
   - **效果**：$101 + 0 > 100$ 判定为 `true`，超支方案绝不因余餐免费误判预算内；当 $S=100, P=0, B=100$ 时判定为 `false`（预算内边界正确）。
2. **BnB 乐观界剪枝一致性 (`RunBranchAndBoundAlgorithm`)**：
   - **原缺陷**：初始化 `env.remainingBudgetCents` 时执行了夹零 `if (env.remainingBudgetCents < 0) env.remainingBudgetCents = 0;`。当 $S > B$ 时，`CanPruneForStrategy` 计算 `lbKnownPrice > remainingBudgetCents`，余餐存在 0 元菜的分支（$0 > 0$ 为 false）误判 `optOverBudget = false`，与终端评估发生逻辑分歧。
   - **修正**：移除该处夹零，保留带符号差额 $B - S$。
   - **效果**：在 $S > B$ 时，$B - S < 0$；由于 $\text{lbKnownPrice} \ge 0 > B - S$ 恒成立，BnB 子树搜索中所有分支均正确保持 `optOverBudget = true`，剪枝逻辑与终端评估保持 100% 严格一致。
3. **响应序列化与契约遵守 (`WritePlanJson`)**：
   - 展示余额 `remainingBudgetKnownCents` 继续遵守现有契约夹零展示为非负数（`remainingKnown < 0 ? 0 : remainingKnown`）；
   - `withinBudgetKnownAmounts` 严格基于全天实际总额判定：
     ```cpp
     const bool withinBudgetKnown =
         remainingKnownValid && plan.priceComplete &&
         (plan.knownPriceCents + intake.knownPriceCents <= config.budgetCents);
     ```
   - `overageCents` 精确反映全天总额超标差额：
     ```cpp
     if (remainingKnownValid &&
         plan.knownPriceCents + intake.knownPriceCents > config.budgetCents) {
       overage = (plan.knownPriceCents + intake.knownPriceCents) - config.budgetCents;
     }
     ```
   - `overBudget` 输出与 `plan.overBudget` 保持同步。
