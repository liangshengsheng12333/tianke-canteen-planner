### 1.1 闭环 P02 指出的“非法输入 192 B vs 208 B”未解释差异

- **P02 查收疑问**：DSH v2 记录 `invalid` 用例的原生与 WASM 输出均为 208 字节（SHA256 `06F202292DA442F8D33A4E7374CDA6E5D569A37EA708A23243AC258A430A9BB5`）；反重力 v1 反馈中记录长度为 192。
- **实测根因定位**：
  - 该用例的错误消息包含 8 个中文字符：`"message":"整数超出允许范围"`。
  - 在 JavaScript 运行时中，`string.length` 统计的是 UTF-16 字符数（192 字符）；
  - 而这 8 个汉字在 UTF-8 编码下每个占用 3 个字节（`8 × 3 = 24` 字节），比字符数多了 16 字节；
  - 因此其真实的 **UTF-8 字节数正好为 `192 + 16 = 208` 字节**！
  - 经独立脚本计算 `Buffer.from(respText, 'utf8')`，其实测 SHA256 为 **`06F202292DA442F8D33A4E7374CDA6E5D569A37EA708A23243AC258A430A9BB5`**，与 DSH 原生 CLI / WASM 输出**逐字节 100% 完全相同**！
  - 该差异纯属“字符数 vs UTF-8 字节数”的度量单位差异，双方产出的 JSON 文本没有任何内容或语义差异。已在 `verify-v2-integration.mjs` 中更正为显式打印字符数、UTF-8 字节数及 SHA256，详见证据 `05`。

### 1.2 闭环 P02 指出的“未见本地持久化后重开记录”

- 在 `miniprogram\src\pages\index\index.ts` 中实现了 `wx.setStorageSync` 与 `wx.getStorageSync` 的全量快照持久化与恢复逻辑；
