## 4. 正确性推导与双重语义分离

### 4.1 双重价格语义的数学定义

本次修正明确分离了两个正交维度的价格语义：

1. **待选方案自身价格完整位 $P_{\text{cand}}(\text{Plan})$**：
   $$P_{\text{cand}}(\text{Plan}) = \bigwedge_{m \in \text{Meals}} \bigwedge_{i \in \text{Items}(m)} (\text{priceBasis}(i) \ne \text{"unknown"} \land \text{unitPriceCents}(i) \ne \text{null})$$
   - **作用域**：搜索状态内部（DP 的 `DpState.priceComplete`，BnB 的 `optPriceComplete`），以及最终方案评估（`plan->priceComplete`）。
   - **比较规则**：在所有策略词典序比较器 `ComparePrice` 中，价格完整方案恒优先于价格不完整方案；未知价格不是零，未知价格方案不因已知金额为 0 而占优。

2. **全天预算核算完整位 $P_{\text{acct}}$**：
   $$P_{\text{acct}} = P_{\text{intake}} \land P_{\text{cand}}$$
   - **作用域**：预算可行性判定（`overBudget`）与预算警示输出（`BUDGET_ACCOUNTING_INCOMPLETE`）。
   - **行为准则**：当 $P_{\text{intake}} = \text{false}$ 时，$P_{\text{acct}}$ 必为 `false`。全天真实花费上限不可知，故任何方案均必须判定为 `overBudget = true`，输出预算不完整警告。

### 4.2 为什么修后 DP 精确支配与 BnB 乐观界恢复安全

1. **DP 精确支配**：
   同阶段前缀 $A$ 与 $B$ 的支配要求 $A.priceComplete == B.priceComplete$。
   - 修前：若已吃未知，$A$ 与 $B$ 均被强置为 `false`。若 $A$ 未知价（已知 0 分），$B$ 已知价（100 分），DP 误认为两方案完整性打平，进而以 $0 < 100$ 判定 $A$ 严格支配 $B$，将优质完整方案 $B$ 剔除。
   - 修后：$A.priceComplete = \text{false}$，$B.priceComplete = \text{true}$。完整性不等直接返回 `false`，两状态互不支配、各自保留。在终端 `EvaluateFullDayPlan` 中，完整方案 $B$ 凭借 `ComparePrice` 成功胜出。

2. **BnB 乐观界剪枝**：
   - 修前：`optPriceComplete = prefix.priceComplete && rem.anyPriceComplete`。当根状态混入已吃未知时，`optPriceComplete` 恒为 `false`。当分支已找到价格完整的 incumbent（$P_{\text{cand}} = \text{true}$）时，兄弟分支的乐观价格被误判为必劣于 incumbent，触发错剪。
   - 修后：`prefix.priceComplete` 正确反映待选前缀，若剩余餐次存在价格完整候选，`optPriceComplete` 恢复为 `true`，准确参与 `cmpOptPrice`，消除了同 tier 低价方案的误剪。

3. **预算判定隔离**：
   在 `IsPlanBetterForStrategy` 中：
   - 当启用预算且已吃未知时，所有候选方案因全天不可核算统一标记 `overBudget = true`，在预算守卫层打平；
   - 随之无损进入策略主序（primary/economy/taste），待选方案自身的价格完整性与已知低价得以正确施展裁决能力，同时顶层完整保留预算风险警告。
