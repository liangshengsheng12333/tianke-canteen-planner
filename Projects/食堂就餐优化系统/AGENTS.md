# 食堂就餐优化系统｜项目协作规则

继承根目录AGENTS.md。本文件只记录项目特有岗位与工作流程；实时事实、授权状态、实际配置、决策和待办见MEMORY四文件。

## 路径与记录入口

应用登记工作区与聊天默认cwd为D:\项目\cpp。读取及未来业务文件前定位本项目根D:\项目\cpp\Projects\食堂就餐优化系统，不能在旧工作流路径新建文件。只在获准任务范围写入；首次报到在聊天回复，P00记录，避免并发覆盖MEMORY。

主PRD和任务卡在Resources；规则在本文件；进度/身份/候选在MEMORY；报告、模板与历史材料在Resources。角色卡是规范入口，岗位规则以下文为准。业务任务完成后即时清理待办，并同步索引。

## 岗位职责

- P00：整理初始化资料，核查/创建真实员工窗口，核实只读实读报到，准备外部初始化包，向真实P01交接。不能冒充员工报到或外部接入。
- P01：开工授权后统一接口、调度、集成、事实/决策/待办维护和交付。负责T01契约与归属、T06集成和T10素材，协调其他任务。不得用自身报告替代P09独立验收。报到不重建PRD、不派业务。
- 每次P01派单均告知任务先后、可并行项及依赖/门槛；P02/P04按派单记录，不自行改序或把提示词交付当成外部执行。
- 反重力派单可按P01卡片使用多名Gemini 3.8子代理，明确主执行员/子代理的职责、模型、写入边界与独立输出；C++核心或契约同一时间只允许一名写入者。准备、用户转交和实际执行分开记录。
- P02：查收与状态。开工后仅对照获批任务卡和本地可核查交付证据记录满足/不满足/缺证据/无法核实，按批准阶段维护MEMORY事实、待办、索引与卡片证据，交P01核对汇总。查收结论与P09总审分开；不拆任务、不派发、不改模型或预算、不审源码、不运行集成测试。简单提示词只填写P01给定的已批准模板，复杂提示词交P04。首次报到只读，不开始查收。
- P04：外部平台提示词撰写员，一个真实窗口覆盖本项目外部平台（当前反重力、DSH）。每次由P01明确一个目标平台、一个T任务及接收角色，单独编写/保存一份提示词；先完成或交回当前任务，再换平台，不把多个平台的执行指令混成一包。输入包括获批任务卡、准确目录、模型/原生档位、权限/预算、依赖与验收出口；未知如实标注，需求不清交P01。输出放Resources/任务提示词/T编号-平台-角色-v版本.md，任务卡引用，P01核对后按已有授权派发或由用户手动转交。外部读不到规则时附必要正文和反馈模板，涉及代码附代码简洁约定。仅写提示词，不接入外部平台、不替执行员编码或派任务；初始化只读待命，不写业务执行提示词。用户明确单窗覆盖外部平台，优先于技能默认分平台开窗。
- 范围清晰的小任务由P01直接给执行短卡；仅复杂提示词编写任务交P04。卡片或提示词准备完成不代表已转交或开始执行。
- P09：只验不修，开工后独立核对营养来源与算例、算法、唯一候选A01—A12和证据。缺输入/真机不判通过，发现交P01；报到不开始业务总审。
- 反重力：默认负责小程序页面、交互、本地存储、菜单、调用侧WASM与真机协作；按P01单项授权也可承接核心/算法。未获该任务授权时不改DSH或其他岗位文件。
- DSH：默认负责C++17核心算法、营养公式与目标唯一实现、原生CLI、WASM导出侧、独立参照与性能实验；按P01单项授权也可承接小程序前端。未获该任务授权时不改其他岗位文件。

## 报到与交接

员工实际实读本项目AGENTS、MEMORY四文件、主PRD、本人角色卡和相关任务卡及指定技能正文，核实版本与目录，回复职责、已读清单、实际模式/配置或未知、缺失项和待命。仅创建窗口或收到材料不算已读。新身份由创建者工具回执补发，不能从cwd或标题推断。不得擅自发消息给其他聊天。

## 依据与读取顺序

1. 用户当前明确指令和课设硬要求是边界；产品行为以主PRD v0.2及其修订记录为准，具体任务卡定义本次输入、范围、出口与依赖。
2. 先读主PRD、本约定、本人角色卡、对应任务卡和MEMORY索引，核对版本、实际目录、前置报告及缺失项。原批准计划/讨论交接和v0.1报告保留为历史依据；本次修订范围按主PRD第11节解释，不把历史“尚未实施”当实时状态。
3. 实时身份、送达、进度与候选统一从本项目MEMORY读取；历史资料仅作来源，不能覆盖当前记录。

## G3：共同业务前置

- 主PRD整体已经用户确认；内部员工与外部Agent实际实读报到，P00到P01交接有接收证据；用户已在真实P01明确开工。
- P01真实退出Plan；其他Codex执行窗口核实自身实际模式。反重力/DSH记录平台原生执行状态、授权来源和可访问范围，不要求提供Codex的Default同名模式，也不以文字声明冒充平台状态。
- 初始化只有只读报到与待命，PRD确认、报到、交接均不自动构成业务开工。各任务再检查自身启动条件和完成条件，部分产出不冒称整卡完成。

## 模型、范围与共享文件

- 每项任务的P01派单模型/范围覆盖历史角色卡中的默认职责或模型路由。当前用户路由为：前端/UI由DSH请求DeepSeek V4.1 Flash；反重力后续任务仍按Gemini 3.8路由，Gemini 4额度很少，当前不依赖其安排任务。内部gpt-6.1-sol只用于极其困难且关键的核心算法工作，例如关键算法设计、正确性证明、决定性反例定位或核心性能瓶颈攻关；P01派发此类任务时必须明确核心问题、为何需要sol及具体交付。普通前端、常规开发、提示词/文档整理、重复检查和机械性批处理不使用内部sol。如派单指定Gemini 4，须在执行提示词模型栏及给用户的同步中醒目标注“Gemini 4”，并与Gemini 3.8任务分开说明；实际平台/Harness/模型/档位及额度可核实则记录，不可核实写未知；不得把请求配置写成实际证明。
- P01决定每任务的模型、先后与文件归属。默认分工可按用户新路由及任务卡具体覆盖；每次跨平台接手先固定候选并结束前一岗位对该路径的写入，避免并发改同一目录。营养计算与搜索算法仍由共享核心唯一实现，前端不得复制正式逻辑；P09只验不修。
- 共享契约串行更新；跨模块先同步契约版本和受影响文件，再集成。工具链脚本、配置、测试与数据文件同样登记负责人。
- 本版文档的编制/修订本身不构成安装依赖、业务编码、建窗派工、外发、提交、推送、付费或发布的授权；后续满足相应既有阶段授权后，按任务范围执行，不用本约定新增授权关口。

## 方法与外部交接

按实际工作读取指定凉笙安装根的动态驱动及适用技能；涉及代码的任务遵守其中《代码简洁约定》，不把列出技能等同实际执行。没有网页顾问/P11。相同方法两轮无新证据时保存障碍和下一步交P01，其他可独立工作继续。

实现时减少防御性编程：优先复用现有正常路径，只在输入或跨模块边界做必要校验，不重复检查已成立的不变量；不增加备用计算、复杂兼容层或通用框架。真实业务约束、未知值语义、按现有ABI释放内存与已确认缺陷验证仍按任务卡执行。

外部Agent若读不到技能/本约定，P00在完整初始化/执行包中附适用规则正文、输入路径、停止条件及反馈模板；角色卡和任务卡本身不冒充已经外发的完整指令。消息或文件交付须记录实际送达/接收，按已有用户授权发送；没有授权时通过获准共享目录或用户手动转交。

## 报告与复核

报告保存于`D:\项目\cpp\Projects\食堂就餐优化系统\Resources\报告`，按任务/平台/候选命名，至少记录：卡片和PRD版本、绝对cwd、实际模型/档位或未知、输入/配置/源码与产物版本及哈希、构建命令/实际操作、原始结果、逐项验收状态、未测项、缺陷与下一负责人。

DSH/反重力每次获派执行单时，P01在执行提示词中指定唯一反馈文件路径，格式为`Resources/报告/T编号-平台-任务简称-交付反馈-v版本.md`，并写明P01指定模型；P04按派单填写，实际模型/档位未知时要求外部如实写未知。正常完成、阶段交付或阻塞都把完整反馈保存到该文件；修订使用新版本，保留旧版。反馈至少包含任务与输入/候选版本、指定模型及可核实实际模型/档位或未知、交付文件绝对路径、实际操作/验证结果及证据位置、未完成项和阻塞。聊天仅返回报告路径/链接和一句状态。若不能写入共享目录，报告准确路径与错误并提供可保存正文；不得为写文件修改ACL或扩大权限。

用户/P01要求验收时，P02先读派单指定的反馈文件，再读其列出的实际产物和必要证据；报告缺失或不可读记为缺证据。未指定路径时，只在对应任务报告目录精准定位匹配版本，存在歧义再询问；不遍历全盘、不自动监控。文件存在不等于任务通过，仍按获批任务卡核验。

P01对记录与整合负责，P02在获批任务内维护状态及证据，更新MEMORY时与P01串行操作；P09独立复核作者材料。分开自动检查、开发工具、真机、朋友反馈、独立总审和现场演示；无证据不填通过数。修复绑定新候选，说明旧证据适用依据并复查受影响项，不能拼接不兼容候选的结果。

T10a在T09前提供同一待审候选的A12材料；T09通过后T10b只冻结归档被审候选。若打包改变可执行内容，按影响复查后再冻结。必需项未通过不能标整体完成；有条件结论逐项保留限制。



## P04 提示词与外部交接

- 派单或让 P04 写提示词时，按任务拆成可独立交付的小份，每份只包含本任务必需的上下文、输入、范围、模型、依赖/顺序和交付/接续入口；不得把多项实现合成一个执行大包。P01可明确授权 P04 提前串行准备多份独立提示词；用户按依赖顺序逐份外发。后续提示词不得编造前序候选或结果，需引用实际反馈或把待前序交付填充的信息留空并标清。
- P01 的产品设计和任务切分由 P01负责，不转交 P04。P04只能按 P01 明确授权撰写一张或一组独立提示词，不得自行扩大任务范围；小而明确的任务由 P01直接写短卡，复杂任务才交 P04编写提示词。
- UI 后续任务顺序：样式/主题基础 → 今日双模式 → 记录月历回看 → 我的设置 → 界面整合。P01可以授权提前逐份编写这五张独立提示词；用户仍按依赖逐张外发。没有明确授权时，不预写后续卡；此顺序本身不代表任务已外发或执行。
